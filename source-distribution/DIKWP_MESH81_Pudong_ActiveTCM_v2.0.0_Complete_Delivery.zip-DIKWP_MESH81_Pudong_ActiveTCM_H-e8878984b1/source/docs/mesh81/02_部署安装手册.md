# 部署安装手册

## 1. 部署模式

### 1.1 本地演示

适用于功能评审和开发者自测，不可接真实患者数据。

```bash
python --version
python run_mesh81.py config-check --config config/integration.json
python run_mesh81.py integrated --config config/integration.json
```

### 1.2 单机院内试点

建议使用受控 Linux 主机、专用服务账号、systemd、Nginx TLS 终止、独立数据盘和集中日志。配置文件放在 `/etc/pudong-mesh81/`，数据库和交换目录放在 `/var/lib/pudong-mesh81/`，程序目录只读。

### 1.3 Docker/Compose

1. 复制 `.env.example` 为 `.env`；
2. 运行 `python tools/generate_secret.py` 生成随机秘密；
3. 替换连接器模板和证书挂载；
4. `docker compose -f docker-compose.mesh81.yml up --build -d`；
5. 检查健康、日志、审计链和合成联调；
6. 未经批准不得将端口直接暴露到互联网。

### 1.4 Kubernetes

`deploy/k8s/` 提供 ConfigMap、Deployment、Service、PVC 和 Secret 示例。生产部署还需由平台团队补充：Ingress/API Gateway、NetworkPolicy、PodDisruptionBudget、备份控制器、日志/指标采集、证书管理、镜像签名和准入策略。

## 2. 环境要求

| 项目 | 最低建议 | 生产说明 |
|---|---|---|
| Python | 3.10+ | 固定补丁版本并纳入漏洞管理 |
| CPU/内存 | 2 核/4 GB | 根据接口峰值和保留数据评估 |
| 存储 | 20 GB | SQLite 试点；更大规模需评估院方数据库适配 |
| 时间 | NTP 同步 | HIS、LIS、PACS、网关必须统一时基 |
| 网络 | 仅必要方向开放 | 禁止数据库对外；使用 TLS/mTLS |
| 账号 | 专用非特权账号 | 禁止 root 运行 |
| 日志 | 本地 + 集中 | 默认不记录 PHI 载荷 |

## 3. 配置步骤

### 3.1 创建环境配置

从 `config/integration.example.json` 或 `integration.container.json` 复制。必须检查：

- `environment` 不应在生产仍为 `demo`；
- 数据库与交换目录应为绝对路径或明确挂载；
- 演示令牌应禁用；
- HMAC/核心令牌从环境或密钥系统注入；
- `trusted_proxy_cidrs` 只包含真实身份网关地址；
- `require_https_headers=true`；
- `phi_logging=false`；
- 三个自治临床动作保持 `false`；
- `core.mode=staging_only`，直到通过院方写回验收。

### 3.2 配置身份

推荐流程：用户登录院方统一身份平台，身份网关验证后向本系统传递受保护头部。本系统只信任来自配置 CIDR 的代理。任何终端直接发送的身份头均不得被接受。

需要确认的属性：主体 ID、姓名显示、角色、科室、机构、会话 ID、认证时间、强认证级别。角色映射必须由院方确认，不能仅按职位名称猜测。

### 3.3 配置连接器

每个连接器包含：ID、类型、方向、端点、认证、超时、重试、映射版本、允许消息/资源、写策略和负责人。将模板复制为现场配置，不要直接修改模板。

### 3.4 配置映射

映射文件必须版本化。至少记录：源字段、目标字段、必填性、类型、代码集、单位、空值、日期时区、重复字段、异常处理和无法表达的残差。

## 4. 启动与检查

```bash
python run_mesh81.py config-check --config /etc/pudong-mesh81/integration.json
python run_mesh81.py qa --config /etc/pudong-mesh81/integration.json
python run_mesh81.py integrated --config /etc/pudong-mesh81/integration.json
```

检查项：

- `/api/integration/live` 返回进程存活；
- `/api/integration/ready` 检查数据库、配置和审计；
- `/api/integration/health` 显示连接器状态；
- `/fhir/R4/metadata` 返回 CapabilityStatement；
- 原临床工作台和集成控制台可访问；
- 审计链验证有效；
- 写回连接器仍处于暂存或关闭状态。

## 5. 反向代理与 TLS

使用 `deploy/nginx/mesh81.conf` 作为示例。真实证书、密码套件、国密、WAF、API 网关、客户端证书和访问控制由院方安全架构确定。不得把演示 HTTP 监听当作生产安全边界。

## 6. 数据库与规模

SQLite WAL 适合单节点试点和可检查原型。若需要多副本写、高并发、长周期大数据或区域级部署，应实现院方批准的数据库适配器，并保留：事务、乐观并发、幂等、审计链、加密、备份、恢复和数据迁移语义。不可仅把 SQLite 文件放在不支持锁语义的共享文件系统上实现多写。

## 7. 升级和回滚

1. 冻结新消息或切换为只读；
2. 完成一致性备份并验证摘要；
3. 导出配置、映射版本和连接器状态；
4. 在预生产环境执行迁移和全量 QA；
5. 生产升级后先只读检查，再恢复入站和出站；
6. 出现不可接受错误时，停止发送、隔离升级后输出、恢复最近密封版本并记录事件；
7. 不回滚审计历史，使用追加事件说明回滚。
