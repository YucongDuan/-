# 完整用户手册

## 1. 适用对象

本手册面向系统管理员、集成工程师、中医临床人员、分诊护理人员、康复治疗人员、质量管理人员、科研观察人员、安全审计人员和患者代理角色。实际账号、执业资格与权限由医院统一身份和制度决定，软件中的角色名称不能代替真实资质。

## 2. 两个工作台

### 2.1 临床工作台（默认 8788）

用于主动采集、四诊表达、病种路径、人工诊疗方案、康复任务、随访、转诊和团队复核。临床工作台的所有诊疗内容均由有权限的人录入或确认。

### 2.2 集成控制台（默认 8790）

用于查看接口健康、入站/出站消息、死信、患者主索引候选、FHIR 资源、同意、签名信封、临床暂存和审计。普通临床用户通常不需要管理连接器。

## 3. 登录和会话

### 演示环境

使用配置中的演示令牌或原系统演示账号。演示身份只用于合成数据。

### 生产环境

用户应先通过医院统一身份平台登录。页面或 API 收到的主体、角色、科室必须来自受信身份网关。发现角色不符、科室缺失、会话过期或异常登录时，应停止操作并联系管理员。

## 4. 临床工作流操作

### 4.1 创建/打开病例

1. 搜索患者或打开已分配病例；
2. 核对患者标识、姓名掩码、出生日期、就诊号、院区和当前接触；
3. 若出现 MPI 候选或身份冲突标记，不得继续高影响录入，先交由授权人员核对；
4. 新建病例时只使用当前任务所需的最少信息。

### 4.2 主动意图采集

记录患者原始表达、观察者、来源类型、时间、精度和状态。系统生成的问题队列用于补全工作流，不是自动诊断问卷。对“推断”或“争议”内容必须保留状态，不能改写为患者明确陈述。

### 4.3 四诊表达账本

望、闻、问、切均保存原始表达、代码、观察者、时间、范围、来源与证据可靠性。录入时：

- 先保留原始表达，再选择代码；
- 不把同名标签强制视为同一语义；
- 临床限定字段只由有资格角色录入；
- 发现单位、时间或观察者错误时追加更正，不静默覆盖审计记录。

### 4.4 病种路径

路径可以是明确、临床确认、语境推断或争议状态，可并行或竞争。选择路径前核对来源、覆盖程度、观察者匹配和当前阶段。系统中的病种包是工作流容器，不自动构成诊断。

### 4.5 人工诊疗方案

方案模块记录医务人员形成的内容。高风险类别要求相应角色和人工复核。系统不会自动生成处方、剂量、穴位组合或急诊处置。任何从外部系统导入的建议都应显示来源并先暂存。

### 4.6 康复与随访

按照“意图—目标—任务—打卡—观察趋势—残差—新问题”维护。趋势只辅助观察，不自动改变治疗、训练或用药。异常情况按医院既有流程处理，不能仅依赖本系统告警。

### 4.7 双向转诊

录入转诊类型、原因、目标机构、必要资料、联系人和期望回转条件。系统只有在接入真实号源/床位接口并获得明确回执后，才可显示实时资源状态；否则显示“目录/元数据”而不是“已预约”。

## 5. 集成控制台操作

### 5.1 首页指标

关注：

- 入站接收/拒绝/重复；
- 出站待发送/重试/死信；
- MPI 未决候选；
- 临床暂存待审核；
- 连接器健康；
- 审计链有效性。

指标反映工程状态，不等于临床质量结论。

### 5.2 入站消息

打开消息可查看：来源、协议、消息 ID、接收时间、原始摘要、解析状态、患者解析、映射版本、资源列表、语义护照和残差。

处理原则：

- `received`：已接收，未必完成解析；
- `processed`：已转换和存储，不等于临床确认；
- `duplicate`：幂等键重复，系统未重复创建；
- `rejected`：协议、安全、权限或数据校验失败；
- `needs_review`：身份或语义仍不确定。

### 5.3 出站消息

创建出站任务前选择连接器、资源/载荷、用途、目标和幂等键。队列状态：

- `queued` 等待；
- `leased` 正在发送；
- `delivered` 对方已接受；
- `retry` 可重试失败；
- `dead_letter` 超过上限或不可重试；
- `closed` 经人工确认关闭。

不得通过反复点击人为制造多个幂等键绕过去重。

### 5.4 死信处理

1. 阅读最后错误、尝试次数和连接器健康；
2. 判断是配置、数据、对方系统、证书、网络还是权限问题；
3. 修复根因；
4. 由有权限人员选择重放或关闭；
5. 重放保留原消息和审计，不修改历史；
6. 高影响消息重放前再次确认对方未实际执行。

### 5.5 患者主索引（MPI）

候选页面显示掩码后的标识、匹配证据和冲突。操作：

- `link`：确认两个标识属于同一患者；
- `reject`：确认不是同一患者；
- `hold`：信息不足，保持未决；
- 禁止自动不可逆合并；
- 链接错误应通过追加纠正解除，并评估受影响数据。

姓名相同不能单独作为合并依据。必须结合权威患者号、证件、出生日期、联系方式、就诊关系和院方规则。

### 5.6 同意与用途

同意记录包含主体、目的、范围、生效/失效时间、来源和撤回状态。系统检查的是“声明的用途是否有相应记录”，不替代法律或伦理判断。撤回后，新的处理应被阻止；历史数据的保留/删除由院方政策执行。

### 5.7 签名信封

签名信封保存载荷摘要、签署者、证书/外部签名标识、时间和验证状态。演示 HMAC 不是真实电子签名。生产文书必须由院方合规电子签名/CA 平台完成，并将验证结果回传。

### 5.8 临床暂存

外部数据或出站回写进入暂存项。审核者依次核对：

1. 患者与就诊；
2. 来源系统与消息；
3. 时间、单位、代码和状态；
4. 映射残差；
5. 目的、同意和权限；
6. 是否属于可自动同步的低风险字段；
7. 是否需要医师、护士、药师或双人批准。

批准只是允许进入既定工作流；不得将批准动作扩展成自动诊断、处方或医嘱。

### 5.9 审计

审计页面按时间、主体、动作、对象、结果和请求 ID 查询。管理员可执行审计链验证。任何校验失败应立即停止高影响写回、保全日志和数据库副本、启动事件响应。

## 6. 协议测试台

### FHIR

上传 Bundle 或单资源，先在沙箱验证。查询支持受控参数。FHIR 资源可用于互操作，不表示对方系统已接受全部语义。

### HL7 v2

粘贴合成 ER7 消息，查看 ACK、PID/PV1/OBR/OBX 解析和资源映射。生产 MLLP 必须限制发送端、消息类型、字符集和最大大小。

### CDA

上传不含外部实体的 CDA 文档。系统提取文档标识、患者、作者、时间和章节并暂存。文档原文和签名仍由权威文档系统管理。

### DICOMweb

查询时使用患者/研究标识，优先元数据。下载影像或上传实例需要更严格权限。STOW 默认关闭。

## 8. 常见错误

- 401/403：令牌、代理信任或角色不足；
- 409：修订冲突、幂等冲突或重复资源；
- 413：消息超过限制；
- 422：协议/字段校验失败；
- 503：数据库、连接器或对方系统不可用；
- MPI `needs_review`：不能确定患者；
- 队列进入 dead letter：需人工处理；
- 审计链 invalid：立即升级事件。

## 9. 退出与隐私

完成操作后退出统一身份会话，关闭共享终端窗口，不把患者信息复制到个人聊天、邮箱、网盘或截图。导出仅在批准目的和安全位置进行。科研角色只能访问经批准的去标识视图。
