# 故障排查

## 1. 服务无法启动

检查 Python 版本、配置 JSON、目录权限、端口占用、数据库可写、环境变量和秘密。先执行 `python run_mesh81.py config-check`，再查看结构化错误。不要通过关闭安全检查解决配置错误。

## 2. 401/403

确认请求来自受信代理或使用正确签名令牌，角色映射存在，时间同步正常，令牌未过期。生产环境不得临时启用演示令牌绕过身份问题。

## 3. HL7 无 ACK

检查 MLLP 起止符、端口、防火墙、字符集、MSH 字段、发送应用白名单和消息大小。抓包需遵循隐私规定。

## 4. FHIR 422/OperationOutcome

检查 resourceType、标识、引用、时间、状态、Bundle 请求字段和允许资源。查看错误位置和映射残差，不要删除未知字段后无记录重试。

## 5. MPI 一直未决

说明缺少权威标识或存在冲突。联系患者主数据团队补充信息，由授权人员链接/拒绝。禁止降低阈值自动合并来减少队列。

## 6. 出站持续重试

检查对方健康、DNS、证书、认证、限流、超时和载荷。确认对方是否已执行。可重试与不可重试错误必须区分。

## 7. 死信堆积

按连接器和错误类型分组，先停止扩大影响，处理根因，再批量重放。高影响业务逐条核对。设置处理时限和负责人。

## 8. 审计链失败

停止写回，备份现状，运行独立验证，检查磁盘、数据库损坏、非法修改和版本兼容。不得删除失败事件或重建一条看似有效的新历史。

## 9. 临床工作台与网关不一致

核对暂存状态、批准记录、核心 revision/If-Match、患者和就诊标识。冲突时保留双方版本并人工解决，不能最后写入者覆盖。

## 10. 性能下降

查看队列深度、慢连接器、数据库锁、磁盘、审计增长、DICOM 查询范围和大文件。限制查询、分批处理、增加索引或迁移存储；不得关闭审计换取性能。
