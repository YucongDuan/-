# 运维、安全、备份与恢复

## 1. 日常运维

每日检查健康、连接器、死信、MPI 未决、临床暂存、磁盘、时间同步、证书期限和审计链；每周检查容量、慢接口、未知代码、重复率、失败趋势和权限变更；每月执行恢复演练或按院方制度执行。

## 2. 日志与隐私

默认日志只记录请求 ID、协议、连接器、状态、耗时和摘要，不记录完整患者载荷。调试 PHI 日志必须经过审批、限定时间、限定人员并在完成后安全删除。日志访问本身也应审计。

## 3. 密钥与证书

- 不在 Git、镜像或配置模板中写真实秘密；
- 从环境、KMS/HSM 或院方密钥系统注入；
- 使用不同环境、不同连接器的独立凭据；
- 设轮换、吊销和到期告警；
- 私钥权限最小化；
- 演示 HMAC 不代替正式 CA/签名。

## 4. 备份

`tools/backup.sh` 使用 SQLite 在线备份 API 复制数据库，再归档其他运行文件并生成 SHA-256。生产还需：异地/离线副本、加密、访问控制、保留策略、备份作业监控和定期恢复验证。

## 5. 恢复

1. 隔离故障节点并保全证据；
2. 选择经过验证的备份；
3. 恢复到空目录；
4. 运行数据库完整性、审计链和配置检查；
5. 在隔离环境回放关键测试；
6. 先只读启动；
7. 核对队列租约、死信、幂等和对方执行状态；
8. 经批准恢复发送；
9. 记录恢复事件和数据边界。

## 6. 事件响应

### 审计链失败

立即停止高影响写回，保留数据库与日志副本，确认是否为损坏、并发、误操作或篡改，不允许通过删除历史修复。使用追加事件记录调查和恢复。

### 患者误关联

冻结受影响病例和出站任务，解除错误链接，评估已传播系统，通知相应责任团队，按院方制度更正并审计。

### 重复医嘱/转诊风险

暂停连接器，查询对方系统实际状态，禁止盲目重放，使用幂等键和业务单号核对，必要时人工关闭死信。

### 凭据泄露

立即吊销/轮换，检查使用记录，扩大日志审计，更新受影响配置并评估数据访问。

## 7. 容量与性能

观察数据库大小、队列深度、消息峰值、P95/P99 延迟、连接池/线程、文件交换积压、DICOM 元数据量和审计增长。超过单节点 SQLite 适用范围时，应迁移到院方批准的数据服务，而不是依靠共享文件多实例写入。

## 8. 变更管理

连接器、映射、角色、代码集、保留策略和临床桥接均属于受控变更。每次变更应有编号、责任人、风险、测试、批准、上线窗口和回滚方案。禁止在生产直接编辑后不留版本。
