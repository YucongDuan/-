# 医院接口对接实施手册

## 1. 对接前提

本发行版没有浦东新区中医医院真实接口文档、网络、账号、证书和患者数据。因此交付的是可配置适配层、标准协议实现、沙箱和验收框架；真实上线必须由医院信息中心、业务科室、厂商、安全、法务/伦理和项目团队共同实施。

## 2. 接口清单模板

每个接口至少填写：

| 字段 | 说明 |
|---|---|
| 接口 ID/名称 | 唯一名称与业务名称 |
| 源/目标系统 | 厂商、版本、环境、负责人 |
| 业务事件 | 何时触发、谁负责、失败后如何处理 |
| 方向 | 入站、出站、双向 |
| 协议/传输 | FHIR、HL7、CDA、DICOMweb、REST、文件；HTTPS、MLLP、MFT 等 |
| 消息/资源 | ADT^A01、ORU^R01、Patient、Observation 等 |
| 主键/幂等键 | 消息控制号、业务单号、资源版本 |
| 患者/就诊标识 | 权威域、格式、跨院区规则 |
| 代码/单位 | 标准、本地码、版本和映射责任人 |
| 安全 | mTLS、令牌、IP、签名、加密、密钥轮换 |
| SLA | 超时、重试、峰值、消息大小、可用性 |
| 数据用途/保留 | 最小必要、同意、保留、删除/撤回 |
| 写回级别 | 只读、暂存、人工批准、自动低风险字段 |
| 验收 | 正常、边界、错误、重复、乱序、恢复、性能 |

## 3. 各系统建议对接

### 3.1 HIS/EMR

优先接收患者、就诊、科室、医师、诊断/问题目录、文档索引和转诊状态。写回从低风险字段开始，如随访任务状态或经人工批准的结构化摘要。诊断、处方、医嘱和签名必须留在权威系统完成。

可选协议：FHIR Patient/Encounter/Practitioner/Organization/Condition/DocumentReference/CarePlan/Task；HL7 ADT/MDM；厂商 REST。

### 3.2 LIS

接收检验申请状态、标本、结果和报告。必须处理结果状态（初步/最终/更正）、单位、参考范围、异常标志、检验时间和更正消息。仅解析数值不能丢失原报告语境。

可选协议：HL7 ORU/OML，FHIR ServiceRequest/Specimen/Observation/DiagnosticReport。

### 3.3 RIS/PACS

同步影像申请、检查状态、报告与影像目录。DICOMweb 用于元数据和受控访问；影像像素数据通常不进入本系统数据库。患者标识和 Accession Number 映射必须经过验证。

### 3.4 预约/号源/床位

FHIR Appointment/Schedule/Slot/Location，HL7 SIU 或厂商 REST。只有当真实接口返回已确认状态且通过一致性校验时，才显示“已预约/已占用”；静态目录只能显示“候选/待确认”。

### 3.5 药房/处方/医嘱

建议首期只读。即使使用 MedicationRequest/MedicationDispense/ServiceRequest，也不得由本系统自治生成或提交。任何写入必须由院方授权、签名、规则引擎和药师/医师流程完成。

### 3.6 统一身份与组织

OIDC/SAML 通常在医院身份网关完成，本系统接收可信代理头或已验证令牌。组织、科室、人员和角色应从权威主数据同步。禁止把任意客户端头当作认证事实。

### 3.7 电子签名

本系统计算待签载荷摘要并调用外部签名平台，保存外部签名 ID、签署者、证书序列、时间、摘要和验证结果。真实签名格式、证书链、时间戳和法律效力由院方平台负责。

### 3.8 区域平台/医联体

转诊、共享文档和随访可通过 FHIR、CDA、REST 或受控文件交换。需明确患者同意、机构边界、共享范围、回执和撤回机制。

## 4. 字段映射流程

1. 获取真实接口样本和字段字典；
2. 标注必填、可选、重复、条件和废弃字段；
3. 确定患者、就诊、申请、报告和消息主键；
4. 确定代码集、单位、日期、时区和字符集；
5. 建立源—规范—目标映射；
6. 对不可表达项建立残差字段，而不是丢弃；
7. 版本化并由业务/技术双签；
8. 执行往返测试、边界测试和历史样本回放；
9. 上线后监控未知代码和映射失败。

## 5. 幂等和顺序

- HL7 使用发送应用 + 设施 + 消息控制号；
- FHIR 使用资源 ID/version 或业务标识；
- REST 使用事件 ID/业务单号；
- 文件使用来源、文件名、批次、摘要；
- 更正/撤销消息不能被当作重复丢弃；
- 乱序消息应暂存并根据事件时间/版本处理；
- 对方超时不等于失败，重试前先查询或使用幂等键。

## 6. 错误与 ACK

错误分为：

- 可重试：网络、超时、对方 5xx、临时限流；
- 不可重试：认证失败、字段非法、未知患者、违反用途、禁用动作；
- 需人工：患者候选、代码不确定、对方执行状态不明、签名校验异常。

HL7 ACK 应返回应用接受/错误/拒绝及错误位置；REST/FHIR 应返回结构化错误。错误日志不得暴露不必要 PHI。

## 7. 安全联调

- 仅使用隔离测试环境和合成/脱敏患者；
- 证书和密钥通过受控渠道交付；
- 明确 IP、端口、方向、DNS 和时间同步；
- 对 webhook 验证签名、时间戳和重放 nonce；
- 对文件验证摘要、批次、权限和原子落盘；
- 对 XML 禁用外部实体；
- 对 DICOM 限制查询和下载范围；
- 记录每次访问的主体、目的、对象和结果。

## 8. 联调阶段

### 阶段 A：契约冻结

完成接口清单、样本、映射、代码集、角色、用途和验收用例。

### 阶段 B：沙箱

在本发行版沙箱中通过正常、缺失、错误、重复、乱序、超大、未授权和回滚测试。

### 阶段 C：SIT

连接厂商测试环境，验证端到端传输、ACK、幂等、重试、时间、编码、证书和故障恢复。

### 阶段 D：UAT

业务人员用合成/脱敏病例验证界面、临床暂存、人工复核、转诊和异常流程。

### 阶段 E：受控试运行

限定科室、病种、用户、时间和数据类型；高影响写回关闭；每日复盘未决匹配、死信和审计。

### 阶段 F：正式上线

通过安全、临床、信息、运维、数据和管理审批后分批开放。每次扩大范围都需重新评估。
