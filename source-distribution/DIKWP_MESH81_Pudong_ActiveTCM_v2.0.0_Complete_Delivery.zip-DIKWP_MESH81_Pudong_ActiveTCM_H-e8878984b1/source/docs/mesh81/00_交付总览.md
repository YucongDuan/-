# 交付总览

## 一、交付目标

本发行版把原有“浦东新区中医医院 28 优势病种主动诊疗—主动康复—双向转诊”公共信息定制原型，升级为可在隔离环境中演示、可与院内接口沙箱联调、可按医院条件部署、可审计并可继续实施适配的工程包。升级不改变临床责任边界：系统不自动诊断、不自动开方、不自动提交医嘱，不替代医师、护士、康复治疗师、药师、电子病历、电子签名或医院质量管理制度。

## 三、升级后的系统边界

### 已实现的通用能力

1. 可配置、可停用、可替换的连接器；
2. 标准协议与传统医院协议并存；
3. 每条消息的幂等、状态、重试、死信和审计；
4. 患者标识不确定性显式保留，禁止自动不可逆合并；
5. 外部数据到临床内核之间设置可逆暂存与人工批准；
6. 每次转换记录原始载荷摘要、来源、映射版本、语义残差、目的和权限；
7. 演示环境可不依赖第三方 Python 包运行。

### 仍需院方/厂商提供的现场条件

- 真实接口文档、字段定义、代码集、测试账号和证书；
- 网络区划、防火墙、域名、TLS/国密策略、时间同步、日志接收地址；
- 统一身份、组织、科室、人员、患者、就诊等主数据权威源；
- 医疗文书签名、处方、医嘱、药品、检验、影像、号源、床位的生产规则；
- 数据使用授权、保留期限、脱敏方案、容灾指标和上线审批；
- SIT、UAT、性能、安全、临床和运维验收。

## 四、建议试点范围

首个试点应选择低风险、可回滚、数据量可控的闭环，例如：

- HIS/EMR 患者与就诊只读同步；
- LIS 检验结果 ORU 或 FHIR Observation 入站；
- PACS 影像目录 QIDO 只读查询；
- 康复随访任务回传到集成暂存区，不直接写回医嘱；
- 双向转诊工单状态同步，但不预占号源或床位。

在上述环节完成数据一致性、身份匹配、权限、审计、故障恢复和人工复核后，再逐步扩大写回范围。
